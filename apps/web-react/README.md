# @klndr/web-react

The React web app: Vite, React 19, TanStack Router and Tailwind v4 on `@klndr/tokens`.

The app chrome and root frame, sign-in/sign-up, the two static pages (privacy,
account deletion), the calendar, the profile, the landing page and the day planner (`/day/<date>`), with its
timeline, activity palette, block editor, category picker, library dialog, checklist and notes. The plumbing
has been real since R.4 — routing with a route guard, Firebase sign-in with the shared `@klndr/core` profile
logic, `@klndr/data` mounted with the API client, the design tokens, and the dev server's `/api` proxy.

The planner's logic is `@klndr/data`'s (`useDayTimeline`, `useChecklist`, `useNotesEditor`,
`useLibraryActions`), so the components only render; see `docs/mobile-port/DECISIONS.md`.

## Running it

```bash
# from the repo root
npm install
npm run dev:api       # the API, port 3001 (in-memory data without FIREBASE_PROJECT_ID)
npm run dev:web-react # this app, port 5173; /api is proxied to 3001
```

Open <http://localhost:5173>. Without an `apps/web-react/.env`, the app runs **credential-free**: Firebase
is not configured, so the gate stays open and the API answers as its `local-dev` user. To use real
accounts, copy `.env.example` to `.env` and fill in the Firebase web config.

```bash
npm run typecheck -w apps/web-react
npm run lint -w apps/web-react             # the react-hooks rules, which tsc cannot see
npm run build -w apps/web-react        # typecheck, then a production build into dist/
npm run preview -w apps/web-react      # serve the build (the API still has to be running)
```

## How it is put together

| Path | What |
|---|---|
| `vite.config.ts` | React + TanStack Router + Tailwind v4 plugins, the `@/` alias, and the `/api` dev proxy |
| `src/styles.css` | Tailwind v4 and `@klndr/tokens/theme.css`; the base layer and touch rules |
| `src/routes/**` | File-based routes. `routeTree.gen.ts` is generated by the router plugin and checked in |
| `src/routes/_authed` | The signed-in half of the app: a pathless layout whose `beforeLoad` sends signed-out visitors to `/login` |
| `src/auth/` | Firebase JS SDK, the auth state and the gate, and the profile through core's `loadOrCreateProfile` |
| `src/data/provider.tsx` | `@klndr/data`'s `DataProvider`, mounted only once auth has settled |
| `src/theme.tsx` | The light/dark preference (`klndr-theme` in `localStorage`) |

The API is only ever called on this origin, so CORS is never involved: in development `/api` is proxied to
`apps/api`, and in production the API is served behind this app (R.6).

## Sharing rules

Logic, data hooks and tokens are shared with the mobile app; **views are not**. `apps/web-react` compiles
`@klndr/core`, `@klndr/data` and `@klndr/tokens` from source — there is no build step for the workspace
packages. It deliberately does not depend on `@klndr/api`, which is the server.
